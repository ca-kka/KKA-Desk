# KKA Desk architecture outline

## Product boundary
KKA Desk is a private, staff/admin-only Windows desktop application. The first implementation is WPF on modern .NET, with a service/view-model separation intended to keep business logic portable later.

## Intended layers
- **Presentation:** KKA-branded WPF shell, navigation, dashboard, document/PDF experience, query and queue views.
- **View models:** UI state, commands, loading/error state, and permission-aware presentation.
- **Services:** authentication/session lifecycle, due-date synchronization, document/query APIs, and diagnostics.
- **Backend:** existing Supabase Auth, Postgres/RLS, Storage, and reviewed Edge Functions where suitable.
- **Local state:** minimal preferences and user-scoped protected session material; no offline cache of client data.

## Identity and authorization
Reuse existing identities where possible. Shared credentials do not automatically provide seamless SSO. MFA/AAL and any OTP/password-change gates must be preserved. The UI is not an authorization boundary: server-side RLS and endpoint checks must enforce role and client assignment.

## Data policy
Online connection is required for client data. Display last-successful sync and stale/unavailable warnings for public due-date data. Do not fabricate metrics when data has not loaded. Keep client data out of diagnostic logs.

## Distribution
Windows-first private installer. Updates notify users and require confirmation. Build artifacts should be generated by Windows CI, reviewed, and tested before distribution.

## Production safety
The repository is separate from the live website/portal repository. Do not deploy changes to production or modify Supabase schema/functions without explicit approval.
